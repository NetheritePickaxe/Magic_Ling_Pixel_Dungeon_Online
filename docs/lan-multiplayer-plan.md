# 局域网联机实现规划

版本：基于 `0.9.7.2`（DesktopMaster，Java 11 / libGDX 1.14 / LWJGL3）  
目标：模块化开发，尽量不改游戏本体；房主正常玩单人，随时"对局域网开放"，加入方输入 IP 即可进入。

---

## 0. 结论摘要

- **同步模型**：选 **主机权威（host-authoritative）+ 行动命令 + 状态同步**，不做确定性锁步。  
  原因是现有代码不具备锁步前提：`Random` 是全局静态生成器栈且部分入口绕过种子（`Random.Boolean()`、`Collections.shuffle`）、攻击等逻辑由动画完成回调驱动、没有行动录制/重放体系。
- **模块形态**：新增独立 Gradle 模块 `:lan`（网络、同步、联机 UI 全部在内），`core` 不依赖它，`desktop` 依赖它。
- **侵入方式**：**独立模块 + 极小桥接层**。  
  core 只加一组静态 Hook 接口和少量调用点（约 10 处），默认空实现 = 纯单机，行为完全不变；  
  联机功能全部在 `:lan` 模块内，桌面端直接以模块依赖方式集成。
- **多人规则（MVP）**：所有玩家同层、时间模式可配置（共享时间线 / **局部回合制**，默认局部回合制）、PvP 可配置（默认关闭）、全队一起换层、房客死亡先旁观。
- **存档隔离**：联机局使用独立槽位/目录，不污染单人存档。

---

## 1. 现状关键事实（调研结论）

- 项目内**没有任何现成联机代码**，现有网络仅为更新/新闻/每日种子等 HTTP 功能。
- 行动入口并非单一：格子行动走 `CellSelector → Hero.handle(cell) → Hero.next() → Actor.process() → Hero.act()`；  
  但物品使用（`Item.execute`）、休息（`Hero.rest`）、搜索（`Hero.search`）、快捷栏/背包 UI 等是**独立入口**。
- 攻击等行动**在动画完成回调中结算**（`Hero.onAttackComplete()` 内才 `attack()` / `spend()`），逻辑与动画有耦合。
- 玩家不操作时 Actor 逻辑线程 `wait()`，世界静止；渲染线程持续跑动画。Actor 线程还会 `wait` 角色移动动画。
- 随机数：`com.watabou.utils.Random` 为进程级静态栈，楼层生成有明确种子基础（`Dungeon.seedForDepth`），  
  但**运行中随机流状态不入存档**，无确定性重放支持。
- 存档 = 主存档 `game.dat` + 每层 `depth*.dat`，基于 `Bundle`（JSON + 反射 + GZIP）。  
  `Level.storeInBundle` 已是较完整的单层持久化快照，但**不含** Actor 调度集合、`Hero.curAction`、动画进度等瞬时状态。
- 第二玩家的渲染可复用 `MirrorSprite`/`MirrorImage`（英雄外观的非 Hero 实体）与 `GameScene.add(Mob)` 链路；  
  注意默认 `HeroSprite`/`MirrorSprite` 直接读全局 `Dungeon.hero`，需要联机侧自定义 Sprite。
- UI 现成组件齐全：`WndTextInput`（输 IP）、`WndSettings` 的 Tab 结构、`RedButton`/`CheckBox`。
- desktop 产物为 fat jar + jpackage 镜像，未混淆；联机随模块一起打包，无需额外启动参数。

## 2. 同步模型选型

| 方案         | 做法                         | 优点                 | 致命问题                                           | 结论     |
| ---------- | -------------------------- | ------------------ | ---------------------------------------------- | ------ |
| A. 主机权威    | 只有主机跑真实逻辑；房客发行动命令，主机广播结果状态 | 无需确定性；天然防不一致；房客实现薄 | 主机负载与带宽略高（LAN 无感）                              | **采用** |
| B. 确定性锁步   | 各端跑同样逻辑，只传输入               | 流量极小               | 全局 RNG 栈、非种子随机入口、动画回调参与结算、集合迭代顺序等都会分叉；改造成巨大且脆弱 | 否决     |
| C. 画面/输入转发 | 房客只看主机画面                   | 逻辑零改动              | 体验差、带宽高、不是真联机                                  | 否决     |

**主机权威下的职责划分：**

- 主机：完整单人逻辑 + 内嵌服务器。每个房客对应一个真实 `Hero`（注册进 `Actor` 调度，视为 ALLY）。
- 房客：**不跑 Actor 逻辑线程**，本地只保留场景渲染、动画、UI 与输入；输入全部变成命令发给主机；  
  收到主机事件后更新本地镜像状态。房客不需要任何确定性。
- 线程模型：网络 I/O 在独立线程；**命令在主机 Actor 线程执行**（与单人输入同路径）；  
  **事件在房客渲染线程应用**（`Gdx.app.postRunnable`），避免跨线程改场景。

## 3. 多人回合与玩法规则（MVP）

SPD 是"玩家不动世界就停"<u>的回合制，多人必须先定规则，建议如下（后续可调）：</u>

1. **<u>共享时间线</u>**<u>：每个玩家是独立 `Actor`（`HERO_PRIO`）。任何玩家行动都会推进世界，</u>怪物照常行动——  
   与单人手感一致，且几乎不用改 `Actor.process`。
2. **空闲语义**：所有玩家都 `ready`（无行动）且无其他 Actor 可动时，世界暂停，与单人一致。  
   某人挂机不阻塞他人，但世界被他人推进时他照样会挨打（UI 给出"危险"提示）。
   **局部回合制开启时**，远处玩家不受他人推进影响，见 §3.1。
3. **同层限制**：MVP 所有玩家必须在同一楼层；任意玩家触发楼梯 → 主机发起**全队换层**，  
   复用现有 `InterlevelScene` 流程，其他玩家落点在换层点附近（参考 `Mob.restoreAllies` 的落点搜索）。  
   不同层各玩各的属于二期（需要多层同时驻留，改动大）。
4. **PvP 可配置（默认关闭）**：房主在开放设置中开关，随房间配置同步到所有端。
5. **端口可配置**：「对局域网开放」窗口提供端口按钮，开放前可改监听端口，持久化到游戏本地目录（默认 `47654`）。
   - 关闭：玩家间 `Alignment.ALLY`，不可互相攻击，范围伤害/负面效果不对玩家生效。
   - 开启：允许互相攻击，玩家的攻击、法术、投掷与范围效果可对其他玩家造成伤害；
     击杀经验归击杀者，死亡玩家物品按现有死亡规则落地、可被拾取。
   - 局中切换由房主操作，切换时全员提示；MVP 阶段不做队伍/阵营细分。
   无论开关，经验、拾取各自独立，谁捡谁得。
5. **死亡**：MVP 房客死亡进入旁观（可观看队友），换层时复活或后续做队友复活；房主死亡 = 局结束（与单人一致）。
6. **人数**：MVP 2–4 人。

### 3.1 局部回合制选项（2026-10-26 追加，已实现）

房主可在开放设置中切换"共享时间线 / 局部回合制"（**默认局部回合制**，局中可切并全员提示）。

- **语义**：以活动玩家（最近有待办行动者）为基准，复用**原版英雄视野（FOV）**判定活动范围——
  调用 `Level.updateFieldOfView(活动英雄, ...)`，只有落在视野内（含墙体遮挡、黑暗、照明、远见天赋、守望者穿草、烟雾等原版规则）
  的角色与 buff 才推进回合；范围外 Actor 冻结，**较远的其他玩家不受这边回合推进影响**。
  靠近的玩家落在同一视野内，仍共享时间。判定基准与"探迷雾""怪物 notice/觉醒"一致。
- **时钟**：每个玩家一条独立局部时钟，活动玩家推进即该时钟推进；切换活动玩家或角色进出范围时
  平移时间轴（`Actor.shiftTime`），保留剩余冷却、**不补跑冻结期间的回合**；关闭选项时全部对齐回当前时钟。
- **实现**：core 仅加 `beforeActorSelection / isActorSchedulable / onActorTimeFixed` 三个钩子与
  `Actor.shiftTime`；区域、时钟、冻结/恢复全部在 `:lan` 的 `LocalTurns` 内。
- **边界**：blob、respawner 等非定位 Actor 跟随当前活动区域；活动范围跟随原版视野规则（视距、遮挡、黑暗、照明、天赋、烟雾），
  不随窗口/摄像机像素大小变化；冻结区域不结算 AI/攻击，跨区域交互以目标进入活动视野为前提。

## 4. 模块划分

```
settings.gradle 新增:  include ':lan'

:lan  （core 不依赖 lan；desktop implementation project(':lan')）
├── net/          帧协议、TCP server/client、心跳、（可选）UDP 房间发现
├── protocol/     消息定义 + 协议版本；快照用 Bundle，命令/事件用紧凑 JSON（复用已有 Jackson）
├── host/         主机侧：会话管理、命令校验与执行、事件采集与广播、全队换层协调
├── client/       房客侧：连接、快照恢复、事件应用、本地输入转命令
├── sync/         快照组装/拆解、实体增量编解码、每玩家 FOV
├── ui/           开放局域网窗口、加入窗口（WndTextInput）、玩家列表、聊天/提示、联机 HUD
└── bridge/       LanBridge：实现 core 的 LanHooks 接口，是桥接调用的唯一入口
```

**依赖方向**：`lan → core`（复用 Hero/Level/Bundle/UI），`core ↛ lan`。  
core 侧只出现**一个无实现的桥接口**，默认空实现 = 纯单机，行为完全不变。

## 5. 核心桥接点（最小侵入清单）

core 新增 `LanHooks`（静态注册 + 默认空实现），调用点控制在以下约 10 处，均为 `if (hook 存在)` 式附加逻辑：

| #  | 位置                                                           | 用途                              |
| -- | ------------------------------------------------------------ | ------------------------------- |
| 1  | `GameScene.create/destroy`                                   | 联机 UI、远端玩家 Sprite 挂载与清理         |
| 2  | `GameScene.defaultCellListener.onSelect`（或 `Hero.handle` 入口） | 房客：拦截本地格子行动 → 发命令，不走本地 `next()` |
| 3  | `Item.execute(Hero, String)`                                 | 房客：物品使用/丢弃/投掷转命令（独立入口，必须单独拦）    |
| 4  | `Hero.rest` / `Hero.search` / 等待按钮                           | 房客：非格子行动转命令                     |
| 5  | `GameScene.update` 中 Actor 线程启动处                             | 房客：**不创建本地 Actor 线程**，改由网络事件驱动  |
| 6  | `Hero.onAttackComplete` 等动画回调                                | 主机：行动结算后采集结果事件（主机逻辑不变，仅附加通知）    |
| 7  | `InterlevelScene` 模式执行前后                                     | 主机：换层协调与楼层快照广播；房客：等待主机换层指令      |
| 8  | `Dungeon.saveAll/saveGame`                                   | 联机局重定向到独立联机槽位，避免污染单人存档          |
| 9  | `Dungeon.init/switchLevel`                                   | 主机：登记额外 Hero、为每玩家初始化视野与落点       |
| 10 | 标题场景与游戏内菜单                                                | 标题"多人游戏"页面；局内"对局域网开放"入口            |

> 桥接层是联机代码与游戏本体之间的唯一接触面；所有桥接调用都只做入队/出队等轻量操作，  
> 不在游戏线程里做网络 I/O。

## 6. 联机流程

### 6.1 房主：单人中开放局域网

1. 游戏内菜单在"兑换码"下方新增"对局域网开放"：端口（默认如 `47654`，开放前可改并持久化）、人数上限、是否允许新玩家、**PvP 开关（默认关）**、**局部回合制开关（默认开，局中可切）**；去掉了原"关闭联机"按钮（房主需退出游戏才结束房间）。
2. 开放时：先存档，再**自动把当前槽位备份到「存档备份」**（文件名带 `SP-` 前缀 + 时间戳）；联机沿用原单人槽位继续存档。
3. 启动内嵌 server（独立线程），窗口显示本机局域网 IP + 端口；可选 UDP 广播房间名，加入方可自动发现。
4. 关闭开放：房客实体从世界中移除（其角色数据留在房主的存档里，下次开放可继续），房主可继续游玩或回到单人。

> 标题「多人游戏」是独立页面，提供 **服务器列表**（已保存服务器 / 直接加入 / 添加服务器）；
> 开房不再有单独的联机存档体系：正常进单人局，局内菜单「对局域网开放」即可，
> 开放前自动在「存档备份」里留一份 `SP-` 前缀的备份兜底。

### 6.2 房客：输入 IP 加入

1. 标题界面「多人游戏」→「服务器列表」：已保存地址独立成页，点击即连；「直接加入」输入 `IP[:端口]` 只连接不保存；「添加服务器」只保存地址（最多 8 条）。
2. 握手：协议版本 + `appVersionCode` + 资源/模组校验，不一致明确提示，不强行进游戏。
3. 首次加入：选职业/命名 → 主机在房主附近生成该玩家 Hero；再次加入：按 `playerId + token` 恢复原角色。
4. 接收**全量快照**（见 §7）→ 本地构建 `GameScene` → 进入联机模式（本地 Actor 线程关闭）。
5. 断线：主机保留其角色为"离线不动"；房客界面提供重连；重连后重新下发快照。

### 6.3 换层 / 存档 / 退出

- 换层由主机统一执行：先 `saveAll`（房主自己的槽位），再将新房主层快照 + 各玩家状态广播，各端一起切场景。
- 房客本地**不写整局存档**（避免脏数据），只保存自己的显示设置与手动添加的服务器列表。
- 房主退出 = 房间解散，房客收到明确提示回标题。

## 7. 快照与增量同步设计

**加入/换层 = 全量快照**（复用现有序列化，成本最低）：

```
Snapshot {
  protocolVersion, gameSeed, depth, branch,
  gameBundle   // 主存档 game.dat 对应 Bundle（剔除主机私有项）
  levelBundle  // 当前层 depth*.dat 对应 Bundle（Level.storeInBundle 已够用）
  players[]    // 每个玩家：playerId、Hero Bundle、pos、名字、皮肤
  hostPlayerId / yourPlayerId
}
```

- 直接复用 `Bundle` 的 JSON + GZIP 编解码，无需引入 Kryo；LAN 下几百 KB 一次性传输可忽略。
- 房客恢复快照后，用"本地 Hero + 远端玩家镜像实体"重建场景；远端玩家渲染参考 `MirrorSprite` 写联机专用 Sprite（不要直接用 `HeroSprite`，它绑死 `Dungeon.hero`）。

**行动中 = 增量事件**（主机每次行动结算后广播）：

```
ActionResult { actorId, kind, ... }        // 移动/攻击/施法/拾取/投掷/等待…，用于房客播放对应动画
CharDelta  { id, pos, HP, HT, buffs, ... } // 受影响的 Char（含怪物与玩家）
LevelDelta { heaps/plants/traps/map 变化 }  // 只在变化时发
FloorEvent { 换层/玩家进出/死亡/聊天等 }
```

- 房客按事件更新镜像并播放动画；**不在本地结算伤害、不跑 AI**。
- 视野：每玩家独立 FOV。MVP 在房客本地按自己 Hero 位置计算迷雾（LAN 信任环境，不做信息裁剪）；需要防窥时再改为主机按玩家 FOV 过滤。
- 校验：每条事件带递增 `tick/seq`；房客发现序号断裂或状态校验失败 → 主动向主机请求重发全量快照（保底自愈手段，也是排障利器）。
- 帧格式：`4 字节长度 + 1 字节消息类型 + payload`；TCP 即可，心跳 5s，超时判离线。
- 二期优化：事件合并、只发视野内变化、快照压缩差分。MVP 不做。

## 8. 桌面端模块化与打包

**决策：放弃 javaagent/字节码织入方向。桌面端与其他模块一样走常规 Gradle 模块化，不做任何运行时类修改。**

### 8.1 模块与依赖

```
settings.gradle:  include ':lan'
lan/build.gradle: implementation project(':core')     // 单向依赖，复用 Hero/Level/Bundle/UI
desktop/build.gradle: implementation project(':lan')  // 桌面端集成联机
core:             只含 LanHooks 接口与空实现，不认识 :lan
```

- 桌面端在 `DesktopLauncher` 启动时做一次显式初始化：`LanHooks.install(new LanBridge())`（仅此一行装配代码），  
  之后所有联机行为由 `:lan` 内部完成。
- 需要"纯单机构建"时，去掉 desktop 对 `:lan` 的依赖与这一行装配即可，core 的桥接空实现保证行为不变；  
  也可用 Gradle 属性（如 `-Plan`）控制是否加入该依赖，避免维护两份源码。

### 8.2 代码边界约定

- `:lan` 内只允许通过 `LanHooks` 接触游戏内部流程；不修改 core 类、不反射篡改私有字段。
- core 侧的桥接调用保持无分配、无阻塞的轻量语义；联机逻辑、网络线程、UI 全部在 `:lan`。
- core 需要新增联机可见信息时，优先在 `LanHooks` 增加通用查询/通知接口，而不是让 `:lan` 反向打补丁。

### 8.3 发布形态

- fat jar：`desktop:release` 会把 `:lan` 一并打进产物，玩家**无需任何额外 JVM 参数或启动器**。
- jpackage/runtime 镜像沿用现有配置，无特殊处理。
- 联机协议版本独立于游戏版本号；握手强校验（见 §6.2）。

| M2 完整行动    | 战斗/物品/休息/搜索/投掷；全队换层；开放前自动备份存档             | 双人合作打过数层，存档可从备份恢复         |
| M3 健壮性     | 断线重连、seq 校验与快照自愈、玩家列表/聊天、房间发现                | 拔线重连可恢复；异常有明确提示            |
| M4 打包与可选构建 | fat jar / jpackage 集成验证；`-Plan` 纯单机构建开关；发布说明 | 联机版与纯单机版均可构建、运行，纯单机行为与现状一致 |

建议 M0/M1 先用 `127.0.0.1` 双实例验证，再上两台机器；全程记录协议日志，便于定位状态分叉。

## 10. 主要风险清单

1. **行动入口遗漏**（物品、快捷栏、自定义 UI 直接调 `Hero`/`Item`）：靠 §5 清单 + 房客端"本地禁止直接结算"兜底审计。
2. **动画回调与网络事件顺序**：房客动画只由主机事件触发，不依赖本地回调；主机侧采集事件要在结算完成之后。
3. **fork 自定义系统**（皮肤、扩展属性、Lua 等）也要进快照与协议校验，否则两端不一致。
4. **多层异步状态**：换层中禁止其他命令，主机串行化处理。
5. **版本不一致**：握手强校验，杜绝"能连上但玩法不同"的隐性坏档。
6. **局部回合制的时钟一致性**：冻结/恢复必须只平移不补跑；`Actor.fixTime` 回拨时同步联机侧时钟；
   暂停点仍需避免"current 停在远端英雄导致主机唤不醒"的旧死锁（暂停前先 `next()`）。
